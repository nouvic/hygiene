01 / The problem

Repositories remember more than code.

Comments and Markdown can carry decisions from a conversation long after the surrounding code changes. A temporary instruction can become apparent policy. A record of disagreement can look like a product requirement. A deleted document can still lend authority to a comment that points to it.

Whether an agent reads or follows any of this depends on its tools and task. Hygiene does not claim to observe a model's context or diagnose its behavior. It asks a smaller, testable question: what instruction-like material is present in this repository?

02 / What it reports

Signals for review.
Not verdicts.

Hygiene uses explicit heuristics. A match is a prompt for human review, and a clean report only means there were no matches under the current patterns and exemptions.

01

Governance in comments

Rules, rulings, and instruction-like language embedded in source comments.

02

Argument residue

Records of rejection or disagreement that may outlive the discussion that produced them.

03

Phantom authority

Comments that cite a document the scanner cannot find in the working tree.

04

Prose growth

Comment and Markdown volume, plus documents whose history shows no net-shrinking revision.

05

Deleted documents

Repository prose that remains retrievable from Git history after deletion.

Design principle
“Precision is the product.”

False positives are treated as first-class bugs. Pattern changes require positive and nearby negative tests.

03 / The boundary

Small enough to inspect.

Runs locally

Your repository contents are not sent to a service.

Bash + Git

No runtime package installation for the core scanner and hooks.

Read-only first

scan writes nothing and always exits zero.

Hooks are optional

Install commit checks only after reviewing the scan.

04 / Try it

One scan. Then tell us what happened.

Clone the repository and point Hygiene at a project you use with a coding agent. Useful findings, false positives, and clean scans are all valuable public-beta evidence.

git clone https://github.com/nouvic/hygiene.git
cd hygiene
./bin/hygiene scan /path/to/your-project

The scan is informational. It does not change hooks, agent settings, or project files.

Help test the premise

Your private repo can stay private.

An anonymized line, its file extension, and whether the finding was useful are enough. Please do not publish proprietary source.

05 / Evidence and limits

The broader problem has evidence. This tool still needs trials.

A public Claude Code report describes feedback accumulating without expiry. An ETH Zurich study found no task-success improvement and over 20% higher inference cost from context files in its evaluated settings.

Neither source proves Hygiene is effective, or that this specific residue is widespread. That is why this is a public beta and why clean scans matter as much as findings.
